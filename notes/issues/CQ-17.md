## Problem

**CQ-17. Coin Gold color-token drift to the Warning hex, in 3 places.**

`game/colors.js` defines `gold` (`#ffd700`, for coins/rewards/prices) and
`warning` (`#ffd479`) as distinct tokens on purpose. Three coin/reward-facing
spots had drifted to the Warning hex or bypassed the token entirely.

Surfaced by an `.impeccable` whole-app critique (same tool/gap as [[BUG-9]]).
The critique's own "fully verified" claim for this finding was itself wrong —
it named `CardThemeScreen.js`, `FramesScreen.js`, `ProfileScreen.js`, and
`DailyBonusModal.js`, none of which actually had the bug (all already import
and use `gold` correctly). Re-verifying against current source found the real
drift in three different files.

## Verified/Fixed 2026-08-18

- `TableThemePicker.js:222` — felt `price` label used `"#ffd479"` (Warning)
  instead of `gold`. Fixed; also removed a stray unrelated Prettier-only
  reformat of a nearby line that had crept into the working tree (no content
  change there).
- `game/frames.js:28` — the shop's "Gold Ring" frame used `"#ffd479"` for its
  own `color` field, contradicting the file's own header comment ("gold
  spots=gold"). Fixed to `gold`. `__tests__/frames.test.js:35` asserted the
  old hex and was updated in the same commit; full suite still green
  (577/577).
- `AchievementsScreen.js:174` — `coinValue` hardcoded the literal `"#ffd700"`
  instead of the `gold` import already used elsewhere in the same file.
  Same rendered color, now token-sourced.

**Left alone, confirmed not drift:** `CardThemePicker.js:186`'s `lockPill`
border also uses `"#ffd479"`, but as a locked-item/caution indicator — a
genuinely different semantic role from coin display, not this bug class.

Commit `7d4e551`.
