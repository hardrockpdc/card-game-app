## Verified 2026-08-15

The BUG-6/PERF-3 framing was accurate as far as it went, but doesn't fully resolve this
ticket's complaint — it narrows it rather than closing it. `game/GameNetwork.js:178-184`
is a shared transport wrapper that adds `protocolVersion` to whatever object each screen
builds — it doesn't enforce any payload shape itself.

**GAME_STATE broadcast shape is consistent across 5 screens, breaks on a 6th.** Conquián,
Rummy, Go Fish, Poker, and Last Card all spread public state directly into the envelope:
`{ type: "GAME_STATE", ...pub }` (`ConquianGameScreen.js:302`, `RummyGameScreen.js:
470-473`, `GoFishGameScreen.js:140`, `PokerGameScreen.js:673`,
`LastCardGameScreen.js:401`). `WhoAmIGameScreen.js:90` instead nests it — `{ type:
"GAME_STATE", state: pub }` — and its own client reads it back as `msg.state`
(`WhoAmIGameScreen.js:155`). Same `type` string, genuinely different envelope shape, and
this 6th screen wasn't covered by the BUG-6/PERF-3 checks (both examined the other 5).

**Client→host action messages also diverge in field naming.** Conquián, Go Fish, and
Poker all use `{ type: "ACTION", action: "<verb>", ...extra }`
(`ConquianGameScreen.js:569` etc., `GoFishGameScreen.js:299-303`, `PokerGameScreen.js:890`).
Rummy instead uses `{ type: "ACTION", moveType, ...extra }`
(`RummyGameScreen.js:714-718`) — same envelope, different key for the verb. Last Card
skips the generic `ACTION` envelope entirely, using distinct top-level message types per
action instead — `PLAY_CARD`, `DRAW_CARD`, `CHOOSE_COLOR`, `LEAVE`
(`LastCardGameScreen.js:932,945,978,1004,1075`) — a structurally different pattern from
the other four games' "one ACTION type + discriminator field" convention.

None of this causes a functional bug today — every host/client pair only ever parses
messages its own game screen produced, so the mismatches are inert in practice. But the
underlying claim ("message shapes aren't consistent across the app's multiplayer code")
is still true, just scoped to specific message kinds/screens rather than a universal
problem. Also worth noting: the ticket's own "un-verifiable without two devices" framing
is inaccurate — this is a static shape-consistency question, fully answerable by reading
source, no live network test required.

## Fix sketch

Low priority, no user-facing symptom. If ever picked up: change `WhoAmIGameScreen.js:
90/155` to spread state like the other 5 screens do, and either rename Rummy's
`moveType` to `action` to match the majority convention, or explicitly document that
Last Card/Rummy intentionally diverge. Matches PERF-3's existing framing that a real
shared/diff protocol is future work — this is cosmetic underneath that, not urgent.
