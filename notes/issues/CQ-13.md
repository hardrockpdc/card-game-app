## Problem

## CQ-13. TypeScript dependency installed but unused

**Effort:** 2 minutes
**Risk if ignored:** None — pure cleanup

### What's happening

`package.json` lists `typescript` as a dependency, but the project is 100% JavaScript (no `.ts` or `.tsx` files, no `tsconfig.json`). Some tooling (Expo's default config) installed it by default.

This caused a small confusion in our last animation session — Claude Code ran `tsc` and got many "errors" that weren't real (just TypeScript complaining about a non-TypeScript project).

### Why this matters

Cosmetic only. Lower install size, cleaner `package.json`, no future confusion.

### The fix

```bash
npm uninstall typescript
```

That's it. Verify the app still builds and runs. (It will — nothing depends on `tsc` for production.)

## Verified 2026-08-15

Fully corroborated by today's filesystem and git history — no discrepancy found.
`typescript` is not in `package.json` (zero grep matches). `npm ls typescript` reports
empty. `node_modules/.bin/tsc` doesn't exist. Commit `3eb638a` ("chore: remove vestigial
typescript dependency (CQ-13)", 2026-06-02) removed `"typescript": "^5.9.3"` from
`package.json` and deleted the corresponding `node_modules/typescript` block (with `tsc`/
`tsserver` bins) from `package-lock.json` — matches `npm uninstall typescript` semantics
exactly. Zero `.ts`/`.tsx`/`tsconfig.json` files exist anywhere outside `node_modules`.
`CLAUDE.md` §2.2 documents both the removal date and the standing "don't run `tsc`" rule.

One benign lockfile artifact: `package-lock.json` still has one `"typescript"` string,
but it's an optional `peerDependency` declaration belonging to `@expo/require-utils` (a
transitive Expo tool) — normal npm lockfile noise, not a reinstalled or lingering direct
dependency. Genuinely fixed, no action needed.
