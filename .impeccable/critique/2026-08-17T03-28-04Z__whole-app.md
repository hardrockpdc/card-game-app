## Overall Impression

The shared-chrome system (GameHeader/StatsStrip/tableThemes) is doing real work and both assessments independently found it disciplined. What's dragging the score is drift, not absence of a system: a documented anti-pattern (`#444` low-contrast hint text) recurring in a new file, and the two biggest/most complex screens (Solitaire, the shop) accumulating one-off colors DESIGN.md's palette doesn't cover. The biggest opportunity isn't a redesign — it's closing the gap between the token system you already have and where the code has quietly drifted from it, plus fixing one real navigation-labeling problem (Shop content hiding under a "Profile" label).

## What's Working

- **`game/tableThemes.js` + GameHeader/StatsStrip** — one shared chrome mechanism, 9 distinct game identities. Exactly the "one system, many tables" DESIGN.md describes, confirmed against actual code, not just the doc.
- **Reduce-motion handling in `Confetti.js`** — subscribes to `AccessibilityInfo.isReduceMotionEnabled()` and the change event, gates the whole particle effect. CLAUDE.md's accessibility rule, actually implemented, not just claimed.

## Priority Issues

**[P0] Invisible instructional copy in the shop**
- **What:** `CardThemeScreen.js:328` — `swipeHint: { color: "#444" }` renders "← swipe to browse →" at ~1.4:1 contrast on the `#1a1a2e` background.
- **Why it matters:** this is the literal anti-pattern DESIGN.md documents as already fixed once. It's recurred, and a second instance of the same stale `#444` sits in `JoinOnlineScreen.js:81` as a placeholder color. First-time shoppers get no visible cue the deck carousel is swipeable.
- **Fix:** swap both to `text-faint` (`#9aa4c4`), the documented floor token.
- **Suggested command:** `/impeccable polish`

**[P1] Coin-economy screens have no named entry point from Home**
- **What:** Card Themes / Frames / Achievements / Stats are only reachable through a Home button labeled "Profile" — despite the coin pill sitting prominently on Home itself.
- **Why it matters:** a player who just won coins and wants to spend them has to guess that "Profile" is where the shop lives. Stimulus (coin pill) and destination (shop) don't share a label.
- **Fix:** rename/relabel that Home entry to reflect it contains the shop, or add a coin-pill-adjacent "Shop" affordance.
- **Suggested command:** `/impeccable clarify`

**[P1] Local vs. Online multiplayer paths look identical**
- **What:** `MultiplayerMenuScreen.js` stacks Host Online / Join Online / Host Local / Join Local as four same-colored buttons, no grouping — despite "no internet needed, local WiFi" vs. "online room code" being PRODUCT.md's stated core positioning.
- **Why it matters:** this is exactly the moment a host with friends already seated picks the wrong mode and burns real time.
- **Fix:** two labeled sections ("Same WiFi" / "Room Code") or distinct accents per mode.
- **Suggested command:** `/impeccable layout`

**[P2] Token drift in the largest screen**
- **What:** `SolitaireGameScreen.js` (3,239 lines) runs its own near-navy palette (`#141a24`, `#1b2433`, `#233047`) — none of it in DESIGN.md's neutral tokens. Detector independently caught 5 off-palette hits here.
- **Why it matters:** this is the exact debt `game/colors.js` was written to kill (935 scattered literals → tokens), re-accumulating in the one screen most likely to be touched again (drag-and-drop, 5 variants).
- **Fix:** route through `game/colors.js`, or extend `tableThemes.js` with a documented Solitaire-rail token.
- **Suggested command:** `/impeccable polish`

**[P3] "Reset Coins to 1000" reads as an exploit**
- **What:** `ProfileScreen.js` has a self-service coin reset directly below the balance — and it's literally where the "Out of Coins" modal in `GameScreen.js` sends players.
- **Why it matters:** for a public Play Store audience, a self-service currency reset undermines an earned-only economy — reads as a bug or cheat code, not a designed recovery path.
- **Fix:** gate behind a dev-only flag, or replace with a real recovery mechanic (small stipend, etc).
- **Suggested command:** `/impeccable harden`
