## Priority Issues

**[P0] Emoji+label recombined into single `Text` nodes — a documented, previously-fixed bug, recurring**
- **What:** `MultiplayerMenuScreen.js`'s four CTAs, `HomeScreen.js`'s "📖 How to Play"/"✕ Quit" links, plus single-node instances in `AchievementsScreen.js`, `CardThemeScreen.js`, `FramesScreen.js`, `DailyBonusModal.js`.
- **Why it matters:** DESIGN.md's own Don't list cites this exact failure by name — a prior version rendered emoji-only after an Android re-layout — and `HomeScreen.js`'s correctly-split `btnLabel` pattern sits right next to these single-node instances in the same codebase. The fix is known and simply hasn't propagated.
- **Fix:** split every joined `Text` into sibling icon/label nodes inside a row `View`, matching `HomeScreen.js`'s existing `btnLabel` pattern.
- **Suggested command:** `/impeccable audit`

**[P1] Coin Gold has drifted to the Warning token across 5 money-facing surfaces**
- **What:** `CardThemeScreen.js`, `FramesScreen.js`, `AchievementsScreen.js` (one line), `ProfileScreen.js`, and `DailyBonusModal.js`'s `GOLD` const all render coins/rewards in `#ffd479` (Warning) instead of the documented `#ffd700` (Coin Gold). Verified directly against each file.
- **Why it matters:** DESIGN.md is explicit that gold does exactly one job — coins, prices, rewards. Five of the highest-frequency money surfaces have swapped that job's color for "caution," undermining the reward feeling at the exact moments meant to feel good.
- **Fix:** replace the `#ffd479` literals in these 5 files with Coin Gold (`#ffd700`).
- **Suggested command:** `/impeccable polish`

**[P1] Host lobby's IP chip contradicts the app's own "no IP typing" positioning**
- **What:** `LobbyScreen.js` renders a prominent "📡 Your IP: 192.168.x.x" chip with a copy button at the top of the host's screen — for a mode PRODUCT.md markets as auto-discovery, no IP typing. Same screen's Start Game button is visually dimmed on an invalid player count (`startButtonDimmed`, opacity 0.4) but carries no real `disabled` prop, unlike every other gated CTA sampled (bet chips, Deal, Join all use real `disabled`).
- **Why it matters:** this is the host's very first screen in the flow PRODUCT.md calls the product's actual differentiator. If the IP chip is a fallback for discovery failures, it isn't labeled as one — as built it reads as a required step, undercutting the pitch at the exact moment a host is trying to get friends connected.
- **Fix:** hide the IP chip behind a "having trouble?" disclosure instead of always-on top placement; give the Start button a real `disabled` state.
- **Suggested command:** `/impeccable clarify`

**[P2] Blackjack's action buttons break the app's own table-theme rule**
- **What:** `game/tableThemes.js` sets Blackjack's accent to gold on forest green, but `GameScreen.js` hardcodes `hitButton: #e94560` (Home's brand red — exactly what DESIGN.md's "Table Overrides Chrome" rule forbids inside a game), plus `dealButton`, `standButton`, `splitButton` in three more colors absent from any token file. Label text is `scaleFont(12)` inside a `minHeight: scale(68)` button.
- **Why it matters:** Blackjack is the simple single-player game most likely to be a new player's first game — its core Hit/Stand loop is both off-brand and visually undersized relative to its own touch target.
- **Fix:** recolor from `getTableTheme("blackjack").accent`/felt family; bump label size to 16-18px.
- **Suggested command:** `/impeccable polish`

**[P3] Shop screens flash "0 coins" on first paint**
- **What:** `CardThemeScreen.js` and `FramesScreen.js` initialize coins with `useState(0)`, briefly rendering "🪙 0" before `getCoins()` resolves — unlike `HomeScreen.js`'s correct `useState(null)` + gate.
- **Why it matters:** it's exactly the wrong place for a flash of wrong data — the screen where a player is deciding whether they can afford something.
- **Fix:** match Home's `null`-then-gate pattern, or show a loading placeholder in the coin slot.
- **Suggested command:** `/impeccable harden`
